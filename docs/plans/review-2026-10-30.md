# Review of `big-bang`, 30 October 2026

A review of the `big-bang` branch on three axes: duplication, security and performance. Seven read-only reviewers covered one area each: the library, the Helper, the engines, the GUI, cross-crate duplication, the workflows and install scripts, and the rules crates with core. Each finding below was checked against the code before it was listed. Known gaps in `BASELINE.md` are not repeated here.

Severity: **H** high, **M** medium, **L** low. Axis: **Sec** security, **Perf** performance, **Dup** duplication (dead code included), **Bug** a correctness fault found on the way.

## Checked and clean

- CSP allows only `'self'`; capabilities grant only `core:default`; `open_url` takes http(s) only; `{@html}` shows only build-time content.
- The Helper's folder is 0700 before the socket is bound; the token is 128 bits, compared in constant time, and needed before any request; requests are capped at 1 MiB.
- Sealed engine runs apply every documented flag; container arguments are never user text; PATH lookup skips relative folders.
- SCID, CBH, CBV, PGN, SGF, KIF, CSA and PDN readers bound their lengths, depths and ratios; zip members go through `enclosed_name`.
- Every action is pinned by commit; every workflow starts at `contents: read`; no `${{ }}` reaches a `run:` body.
- Twenty thousand mutated records per Variant through `bragd_games::replay` and `apply` gave no panic. Backgammon doubles stay under 0.2 ms per turn.
