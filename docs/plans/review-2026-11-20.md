# Weekly review, 20 November 2026

A review of everything on `master` since the [review of 30 October](review-2026-10-30.md): about 150 commits, which added the Bragd server and Play with Friends, the online clients for Lichess, Lishogi and OGS, Peers and the Position store, Clubs with Tournaments, Leagues and rating lists, the Ur solver, engine matches, and six Sources. Four axes: duplication, security, performance and usability. Read-only reviewers covered one area each (the server and its SQL, the online clients, Peers and the Position store, Clubs and pairing, the Tauri backend and core, the workflows and packaging, the rules crates, the engines with the Helper and the library, and the Svelte pages), and every finding below was checked against the code before it was listed. The 30 October findings were re-checked where the new code could repeat them: R1, R5, R7, R8, R10, R29 and R33 hold; R6's pattern (a path the page names, written by Rust) is back in new commands (#451, #452).

The UI check and the screenshots could not be run in this session, so no pictures were looked at. The two screens this branch changes in appearance are marked in their docs pages for a retake (`peers-1100.png`, `peers-sharing-1100.png`); the rest of the changes draw nothing new.

Severity: **H** high, **M** medium, **L** low. Axis: **Sec** security, **Perf** performance, **Dup** duplication, **Bug** a correctness fault found on the way, **Use** usability. Fixed means on the review branch (pull request *Weekly review 2026-11-20*); the rest are issues in the 1.0.0 milestone.

## Checked and clean

- JWT: `alg` pinned to HS256/ES256/RS256, `none` refused, signature over the exact bytes, `exp`/`aud`/`role` checked, a missing `exp` refused. Every `me` comes from the verified `sub`; RLS is the first read in every request. All SQL values are bound. Throws are the referee's, rejection-sampled. Clock charged from the database's `now()`.
- OAuth: PKCE with S256, a 16-byte state, loopback on 127.0.0.1 only, a 64 KiB and 5 s limit on the redirect request. Tokens in the keychain only, sent as `Authorization: Bearer`, never in URLs, logs or texts, revoked on sign-out. TLS through the platform verifier everywhere but the JWKS fetch (fixed).
- Pairing: SPAKE2 over both TLS keys, proofs bound to the TLS exporter, five tries in two minutes, single use; every non-`Pair` request re-checks the pinned key; request and reply sizes bounded; the Position store's merge rule is a total order per key, and the sync's cursors converge (three-Peer test).
- Engine stdin: set-up positions only through `seam::position` (control characters refused); opening lines validated by `bragd_games::replay`; option values checked. Archive member and file names from every Source are filtered; downloads capped and timed; the zip members go through `enclosed_name`.
- Library and Club writes are atomic (`fs::replace`) and transactional; every stored format has a version, a migration and a fixture, and a newer file is refused before it is touched.
- Rules: Ur's paths, captures, rosettes and the solver's values (checked against an independent DP and published figures); backgammon's bar, maximal-dice and bear-off rules and the opening throw; the draughts, go and shogi record boards bounded on hostile input; SAN and FEN edge cases; no clock in any rules test.
- Workflows: every action pinned by commit, every container by digest, every download checksummed, write tokens only in jobs that build nothing, `continue-on-error` only on the attestation step; `verify` fails on a missing, extra, empty or mismatched release file.
- CSP and capabilities unchanged and tight; `{@html}` only on build-time content; `open_url` http(s) only; every page clears its timers on leaving.
